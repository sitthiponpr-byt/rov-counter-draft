# RoV Counter Draft

เว็บไซต์ร่างรุ่นแรก (v0.1) สำหรับช่วยดูตัวเลือกแก้ทางในเกม RoV: เลือกฮีโร่ฝ่ายตรงข้าม 5 ตัว กำหนดเลน แล้วดูตัวเลือกของทีมเราที่ **เอกสารอ้างอิง** ระบุไว้ พร้อมเหตุผล ตัวเลือกสำรอง และข้อจำกัด

> **อ่านก่อนใช้ / ก่อนเผยแพร่**
> - ข้อมูลแก้ทางมาจากเอกสารเดียว "สรุปแก้ทาง RoV 2026 ฉบับ QZADD" (QZADD / GAS TOPUP) ซึ่งอ้างอิงการสัมภาษณ์ผู้เล่น **ไม่ใช่สถิติการแข่งขัน** และไม่ทราบแพตช์
> - **ดาว** 3 = แก้ทางได้ดีที่สุด · **หัวกะโหลก** 3 = เราห้ามเลือกมากที่สุด (เจ้าของโปรเจกต์ระบุ ยังไม่ได้ยืนยันกับ QZADD)
> - ชื่อฮีโร่ในช่องคำแนะนำถูกอ่านจากภาพ ส่วนใหญ่ **ยังไม่ผ่านการยืนยันโดยมนุษย์** (หน้าเว็บติดป้ายสถานะทุกตัว)
> - **สิทธิ์เผยแพร่ซ้ำข้อมูลของ QZADD ยังไม่ได้รับการยืนยัน** ดูหัวข้อ "ก่อนเผยแพร่"
> - ไม่มี win rate / pick rate / tier / คะแนนเมตา เพราะไม่มีแหล่งข้อมูลที่ตรวจสอบแล้ว
> - เว็บนี้ไม่ใช่เว็บทางการของ Garena

## ใช้งานในเครื่อง (Windows)
ต้องมี Node.js 20 ขึ้นไป (ทดสอบกับ Node 24)

```bash
npm install
npm run dev
```

เปิดที่อยู่ที่ Vite แสดง (ปกติ http://localhost:5173)

> **Windows PowerShell แจ้ง "running scripts is disabled on this system"?** นั่นคือการตั้งค่าความปลอดภัยของเครื่องที่บล็อกไฟล์ `npm.ps1` ไม่ต้องแก้การตั้งค่าเครื่อง ให้เรียกแบบ `.cmd` แทน:
> ```bash
> npm.cmd install
> npm.cmd run dev
> ```
> (หรือใช้ Command Prompt / Git Bash ซึ่งใช้ `npm` ได้ตามปกติ)
> อย่าเปิดไฟล์ `dist/index.html` ด้วยการดับเบิลคลิก เบราว์เซอร์จะบล็อกสคริปต์เมื่อเปิดผ่าน `file://` ให้ใช้ `npm.cmd run preview` แทน

| คำสั่ง | หน้าที่ |
|---|---|
| `npm run dev` | รันเว็บสำหรับพัฒนา |
| `npm test` | ทดสอบตรรกะแนะนำทีมและหน้าเว็บ (Vitest) |
| `npm run typecheck` | ตรวจ TypeScript |
| `npm run build` | build production ลง `dist/` แล้วตรวจอัตโนมัติว่าไม่มีภาพ/ไฟล์ต้นฉบับ/ข้อความต้องห้าม (`scripts/check-dist.mjs`) |
| `npm run preview` | ดูผล build ที่ `dist/` |
| `npm run check` | typecheck + test + build ครั้งเดียว |
| `npm run build:data` | สร้าง `src/data/*.json` ใหม่จาก `data-source/` (ต้องมีโฟลเดอร์ `data-source/` ในเครื่องเท่านั้น) |

## วิธีแนะนำทีม (heuristic ยังไม่ผ่านการพิสูจน์)
- ดาว: 3 ดาว = แก้ทางได้ดีที่สุด ดาวน้อยลง = แก้ทางได้น้อยลง (เจ้าของโปรเจกต์ระบุ 2026-10-22 ยังไม่ได้ยืนยันกับ QZADD) · หัวกะโหลก 3 อัน = ห้ามเลือกมากที่สุด (ใช้เรียงรายการห้ามเลือก)
- ลำดับการเลือก: ไม่ซ้ำฮีโร่ในทีม → เติมเลนให้มากที่สุด → ดาวรวมสูงสุด → สอดคล้องกับ ROV META → เทียร์ ROV META → ตัวตนที่ยืนยันแล้ว → บทบาทหลากหลาย → ตัวอักษร

(รายละเอียดเดิมด้านล่าง ข้อ 2 และ 4 ถูกปรับตามนี้แล้ว)
1. ผู้ใช้เลือกศัตรู 5 ตัว (ห้ามซ้ำ) และกำหนดเลน (หนึ่งเลนต่อหนึ่งตัว) ฮีโร่ที่เอกสารมีข้อมูลเลนเดียวจะถูกตั้งเลนให้อัตโนมัติ
2. ตัวเลือกของแต่ละเลน = ฮีโร่ในกลุ่ม "เราควรเลือก" ของแถว (เลน, ศัตรู) นั้นในเอกสาร ทุกตัวนับว่า "มีหลักฐาน" เท่ากัน
3. ตัดออก: ตัวตนอ่านไม่ได้, ตัวตนขัดแย้ง, ตัวที่ศัตรูเลือกไปแล้ว (สมมติฐานโหมดดราฟต์), และ unverified ถ้าผู้ใช้ปิดสวิตช์
4. เลือกทีม 5 เลนโดย: ไม่ซ้ำฮีโร่ในทีม → เติมเลนให้มากที่สุด → ตัวตนที่ยืนยันแล้วก่อน (มนุษย์ > ระบบ > ยังไม่ยืนยัน) → บทบาทหลากหลาย → ลำดับตัวอักษร (เพื่อให้ผลคงที่)
5. ถ้าเลนใดไม่มีข้อมูล จะแสดง "ข้อมูลไม่เพียงพอ" และไม่สร้างคำแนะนำขึ้นเอง
6. คะแนน 3 ชนิดแยกกัน: แก้ทาง (จำนวนเลนที่มีตัวเลือก ไม่ใช่โอกาสชนะ), ความสมดุล (จำนวนบทบาทที่ครอบคลุม — heuristic ที่ตั้งเอง ยังไม่ทดสอบ), เมตา (ไม่มีข้อมูล ไม่คำนวณ)

ข้อจำกัดที่ทราบ: ฮีโร่ 39 ตัวไม่มีข้อมูลแก้ทางเมื่อเป็นศัตรู · ข้อมูลตัวตนฮีโร่มนุษย์ยืนยันแล้วเพียง 6 เซลล์ · บทบาทฮีโร่มาจากเว็บแฟนอิสระ (ROV META แพตช์ 1.64) ไม่ใช่ทางการ · Riktor ยังไม่มีชื่อไทย/บทบาท

## เผยแพร่ผ่าน GitHub Pages (ยังไม่ได้ทำ — ต้องสั่งก่อน)
โปรเจกต์นี้ **ยังไม่ใช่ git repository** และยังไม่ได้ push หรือเผยแพร่อะไร ชื่อ repository จริงยังไม่ทราบ จึงตั้ง base path ให้อัตโนมัติจากชื่อ repo ตอน build บน GitHub Actions (`VITE_BASE=/<ชื่อ repo>/`) ส่วนในเครื่องใช้ path แบบสัมพัทธ์ (`./`)

ขั้นตอน (เมื่อพร้อมและได้ผ่านรายการ "ก่อนเผยแพร่" แล้ว):
1. สร้าง repository บน GitHub (แผนฟรีใช้ Pages กับ repository สาธารณะ ตรวจเงื่อนไขล่าสุดของ GitHub อีกครั้ง)
2. ในโฟลเดอร์โปรเจกต์: `git init`, `git add .`, `git commit`, `git branch -M main`, `git remote add origin <URL ของ repo>`
3. ตรวจก่อน push: `git status` ต้องไม่เห็น `data-source/`, `RoV-Counter-Draft/`, `reference-icons`, `review-tool.html`, `node_modules`, `dist`
4. `git push -u origin main`
5. บน GitHub: Settings → Pages → Build and deployment → Source = **GitHub Actions** workflow `Deploy to GitHub Pages` จะ build, ทดสอบ และ deploy ให้
6. หน้าเว็บจะอยู่ที่ `https://<ผู้ใช้>.github.io/<ชื่อ repo>/`

อย่าใส่ token หรือ secret ลงในไฟล์ใดๆ ไฟล์ workflow ใช้สิทธิ์ของ GitHub Actions เอง ไม่ต้องใช้ token ส่วนตัว

- [ ] ได้หลักฐานอนุญาต/เงื่อนไขการใช้ซ้ำข้อมูลจาก QZADD / GAS TOPUP (ลิงก์โพสต์ต้นฉบับหรือหนังสืออนุญาต) ตอนนี้ไม่มี
- [ ] ยืนยันความหมายดาว/หัวกะโหลก และแพตช์ของเอกสาร (ถ้าได้) แล้วอัปเดต `COUNTER-DATA-PLAN.md`
- [ ] ตรวจโดยมนุษย์เพิ่ม (เครื่องมือใน `data-source/matching/review/`) โดยเฉพาะช่องที่ถูกแนะนำบ่อย
- [ ] ตรวจรายชื่อฮีโร่/บทบาทกับแหล่งทางการ
- [ ] ยืนยันว่า `dist/` ไม่มีภาพของบุคคลที่สาม (`npm run build` ตรวจให้อัตโนมัติ)
- [ ] ตรวจเงื่อนไข fan content ของ Garena ถ้าจะใช้ชื่อ/โลโก้/ภาพฮีโร่ (เวอร์ชันนี้ไม่ใช้ภาพฮีโร่เลย)
- [ ] ตรวจข้อความในหน้า "เกี่ยวกับข้อมูล" และเครดิตให้ตรงกับเงื่อนไขที่ได้รับ

## การปรับปรุงข้อมูล
1. อัปเดตไฟล์ใน `data-source/` (เช่น ผลตรวจมนุษย์ใหม่)
2. `npm run build:data` สร้าง `src/data/*.json` ใหม่ (เฉพาะข้อความ)
3. `npm run check` แล้วค่อย commit ผลลัพธ์ใน `src/data/`
